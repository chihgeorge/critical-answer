## Problem Statement

During play, every phone except the one on turn is idle, and the host is tied to judging: a team says its answer out loud and the host presses 答對 / 答錯・重答 / 答錯・逃跑. A `multipleChoice` question kind already exists (team picks on `/play` via `TEAM_SELECT_OPTION`), but the host still judges it; `docs/designs/multiple-choice-questions.md` explicitly deferred auto-judging. The default bank (`data/question-bank.json`, 5 rooms + boss, 48 questions) is all `text` questions, so nothing can be auto-judged today.

## What Makes This Cool

The team on turn picks and **locks** an option on its phone, the TV holds a short beat, then reveals. Nobody has to stand at the host page judging, so the host can play too. (User's words for the most fun version: the team on turn locks in, then the big-screen reveal.)

## Constraints

- Turn order is unchanged: only the team on turn answers.
- Answer text must never reach any client before it is revealed (`publicQuestion()` field-picking; `npm run check:bundle`).
- Bank text never enters the LLM narration prompt (prompt-injection rule; see TODO "Host 自訂題庫文字進 LLM prompt 前的內容審核").
- The production server keeps its own stored bank (BankStore); changing `data/question-bank.json` only affects a fresh seed.

## Premises (agreed)

1. Turn order stays the same; waiting teams only watch.
2. Pick, then lock. A team may change its pick until it presses 鎖定. Lock is final. The server judges the lock against `correctIndex` immediately; the host no longer judges `multipleChoice` questions.
3. After a wrong lock the team chooses on its phone: **重答** (the options it already got wrong are greyed out and cannot be picked; it answers again on its next turn) or **逃跑** (easier question, current flee rule).
4. `text` questions stay host-judged. Both judging flows coexist; auto-judging applies only to `multipleChoice`.
5. New default bank: about 48 questions, all four-option multiple choice, one theme mix per room (Taiwan general knowledge, pop culture such as music, anime and games, fantasy/adventure), difficulty rising room by room. Claude drafts, the user reviews. Reseeding the production bank is an explicit, separate user decision.
6. Reveal splits by outcome (revised after the Codex challenge):
   - **Correct:** the TV holds a short beat, lights up the correct option and fades the others, then auto-advances to the next question after a few seconds. The host can press 下一題 early.
   - **Wrong:** the TV marks only the option the team picked as wrong and says the team is deciding. The correct option is **not** revealed, so retry stays meaningful. Fleeing also never reveals it (existing rule D5). A question fled after a wrong lock does count as revealed for dealing, though: the room saw which option was wrong, so it is not dealt to another team until the bank runs out (/review, 2026-10-25).
7. Boss room: same rules as other rooms this round, as a stopgap. The user wants the boss stage redesigned later (separate TODO).

## Cross-Model Perspective (Codex, cold read)

- Coolest version: waiting teams privately lock a prediction while the active team answers; predictions show on the TV at reveal and charge a shared "lantern" for the boss. Not adopted this round (overlaps the later boss redesign and the waiting-team-reactions TODO).
- What excites the user: "the TV does a dramatic reveal; the system judges, so the host can play too."
- Halfway tool: Quizle (four-choice phone answers, server judging, reveal flow); reference only, its Go server and free-for-all scoring don't fit.
- Weekend build: one vertical slice with a few MC questions first, the full bank after a real round. Adopted as approach C.
- Challenged premise (High): lighting up the correct option after every lock makes retry free. **Accepted**: premise 6 now splits the reveal by outcome.

## Approaches Considered

- **A. One PR with everything** (engine + UI + 48-question bank). Rejected: if a real playtest changes the flow, the reviewed bank may need another pass, and the PR is large.
- **B. A plus waiting-team predictions.** Rejected for now: biggest scope, overlaps the later boss redesign.
- **C. Two PRs (chosen).** PR 1: the full engine and UI with about 6 sample MC questions. PR 2: rewrite the 48-question default bank after a real round.

## Recommended Approach: C

### PR 1: engine and UI

- **Lock message.** New client message `TEAM_LOCK_OPTION { questionId }` (E11: it locks the server's `currentSelection`), sender team derived from `connTeam` like `TEAM_SELECT_OPTION`. Rejected unless: the sender is the team on turn, the current question is `multipleChoice`, `questionId` matches, `optionIndex` is in range and not eliminated for this question, and no reveal or pending wrong answer is open. Rejected for `text` questions.
- **Two judging paths, enforced on the server.** `HOST_JUDGE` is rejected for a `multipleChoice` question (the UI hiding the buttons is not enough: a stale or second host page could still send it). The only host action on an MC turn is the stuck-team fallback below.
- **Sequencing.**
  - Correct lock: the room calls the existing `answerQuestion(…, correct=true)` at once. Scoring, room advance, boss phase, narration event and `eventSeq` bump happen exactly as today.
  - Wrong lock: the room does **not** call `answerQuestion` yet (it needs the retry/flee choice in the same call). It records a pending wrong answer `{ teamId, questionId, optionIndex }`, bumps `eventSeq` for the broadcast only, and fires no narration. The turn does not advance.
  - The choice arrives (`TEAM_WRONG_CHOICE { questionId, choice: "retry" | "flee" }` from that team, or the host fallback): the room calls `answerQuestion(…, correct=false, choice)`, clears the pending wrong answer, and the existing `incorrect-retry` / `incorrect-flee` narration and turn advance happen then.
- **Wrong reveal lifecycle.** The pending wrong answer is its own public field, separate from today's `reveal` (`AnswerReveal`, correct answers only). It starts at the wrong lock and ends when the choice arrives. While it is open: `TEAM_SELECT_OPTION` / `TEAM_LOCK_OPTION` are rejected, `HOST_NEXT` is ignored, and the TV shows state ⑤.
- **Host stuck-team fallback (user decision).** On an MC turn the host page offers 重答 and 逃跑 for the team on turn, both when the team has not locked (phone offline, team away) and when a wrong answer is pending without a choice. The host picks; the room applies `answerQuestion(…, correct=false, choice)`. Without a lock nothing is eliminated. The fallback's look and when it appears are open design questions; its effect is not.
- **Eliminated options.** Keyed by question id (`{ questionId, options[] }` per team), so it is stale-proof when a shared boss question rotates for reasons other than this team. Retry adds the wrong option; a different current question id means an empty set. In the boss phase all teams share one set for the shared boss question: the TV already shows every wrong pick publicly (state ⑤), so a per-team set would hide nothing.
- **State.** The eliminated sets and the pending wrong answer live in the game state and the room snapshot, with a `restore()` backfill (same pattern as `currentSelection ?? null`). `correctIndex` never goes to clients.
- **Reveal and auto-advance (revised by E2–E4, E12).** A lock is held on the server for 2 s as `pendingLock` (everyone shows 🔒), then judged; the outcome STATE is the moment every client shows the result, with no client beat timer. Auto-advance after a correct reveal uses an in-memory timer, not the Durable Object alarm: max(8 s, narration arrival + characters ÷ 4 per second + 1 s), capped at 15 s; recomputed on a host narration edit. HOST_NEXT cancels it; the timer only closes the reveal it was set for. A restart drops a pending lock and the reveal, as today.
- **Screens.** `/play`: option list, 鎖定 button (disabled until a pick), greyed eliminated options, retry/flee buttons after a wrong lock. `/screen`: the beat, then the correct or wrong reveal (states ④ and ⑤ in the sketch). `/host`: no judge buttons on MC questions; shows the lock and the result; keeps 下一題 and the stuck-team fallback.
- **Sample bank.** 6 MC questions added to the bundled bank's first room so PR 1 is playable; the rest stay `text` until PR 2. For the playtest on production (user decision), the 6 questions are also given to the user as a list to add to room 1 through `/bank-editor`, which already supports MC; no reseed.
- **Accepted:** after three wrong locks on a four-option question only the correct option is left, and the next retry is a free correct answer. It cost three turns, so this stays as is.

### PR 2: default bank rewrite

48 new four-option questions, themed per room, difficulty rising; distractors written first, one or two joke options allowed, every wrong option clearly wrong, the correct option not the longest. The user reviews the draft before it lands. Reseeding production is a separate user call.

PR 2 needs no editor work: `/bank-editor` already authors `multipleChoice` questions (v0.5.0.0).

Wireframe (rough, flow only; pixel art comes from /plan-design-review): `~/.gstack/projects/critical-answer/phone-answering-sketch-20261024.png` (five states: phone pick and lock, phone after a wrong lock, phone while waiting, TV correct reveal, TV wrong reveal). ## Design decisions (/plan-design-review, 2026-10-24)

Mockups: `~/.gstack/projects/critical-answer/designs/phone-answering-tv-20261024/`. D1–D3 from the first session; D5–D14 from the second (D4 was its scope question, not a design decision).

- **D1. TV option layout (`layout-B.png`).** On an MC question the four options stand on the wall to the left and right of the monster: A and C on the left (x 22–338), B and D on the right (x 622–938), rows at y 212 and y 290, each tile 316×62. The monster, the question panel, the nameplate and the dialogue box keep their current size and place; the two wall torches are hidden behind the tiles. Tile: cream face, 4px `--k` outline, `--cream2` bottom bevel, 24px Cubic text, about 10 characters per line; a 30px `--k` letter chip with the A–D letter in Press Start 2P (`--turn2`). `text` questions keep today's layout.
- **D2. Phone order on the team's own MC turn (`phone-A.png`).** Top to bottom: the 輪到我們了 ribbon, then one `Panel tone="turn"` holding the four option buttons and the 鎖定 button, then the 正在面對 card, the score card and the branch panel. All four options and 鎖定 fit in one iPhone SE screen (375×667) with no scrolling. Option buttons are 56px tall with the same A–D letter chip as the TV; the picked option is `--danger` with white text and a "◀ 已選" label, so the pick never relies on color alone. 鎖定答案 is a 62px `--ok` button under the options. On any other turn the order stays as today.
  **Update (v0.18.0.0):** the turn panel now starts with the question text in a dark strip, and on an image or YouTube turn the media sits right under the ribbon, before the cards. This screen's fit target is now an iPhone 12 (390×844). See `docs/designs/phone-question-text.md`.
- **D3. Host thumb zone on an MC turn (`host-A.png`).** The 答對 / 答錯 judge buttons are replaced by a `Panel tone="lav"` status box in the same slot: 22px main line plus a 14px hint. Lines: 等{隊名}鎖定答案… → {隊名}鎖定了 {letter}… → 答錯！等{隊名}選重答或逃跑 → 答對！(the existing 下一題 button then takes the slot as today). Under it, labelled 隊伍卡住時：, two 48px buttons 替{隊名}選・重答 (`retry`) and 替{隊名}選・逃跑 (`flee`): smaller than the 78px judge button so they read as secondary. When they appear: D11. The host's option rows carry the same A–D chips; the team's current pick keeps today's `--turn` highlight.
- **D5. Phone after a confirmed lock (`lock-A.png`).** The option list stays in place. The locked tile stays `--danger` with white text and its label changes from "◀ 已選" to "🔒 已鎖定"; the other three tiles turn grey (`--cream2` face, `--dim-ink` text, `--dim-line` outline, no bevel) and stop responding. The 鎖定答案 button becomes an unpressable `--lav` bar (styled, not `:disabled` opacity) reading 已鎖定！看大螢幕揭曉 ▶. The same list later shows eliminated options as grey on a retry.
- **D6. Lock in flight (`lock-P.png`).** Pressing 鎖定答案 switches the button at once (client-side, before any server reply) to a `--ok` bar reading 鎖定中… that cannot be pressed, and the options stop accepting picks. If no `STATE` confirming the lock arrives within 3 s, the button and options return to their pre-lock state and a 14px line under the button reads 沒送出，再按一次. A confirming `STATE` at any point moves to D5.
- **D7. Phone after a wrong lock (`wrong-A.png`, retry turn `wrong-N.png`).** Shown after the D10 beat. The list stays. A 22px heading 答錯了！要怎麼辦？ with a small `--danger` ✕ chip sits above the options. The wrong tile turns grey like the others (D5 grey) with a `--dim-line` letter chip and a `--wrong` "✕ 答錯" label, so the mark never relies on color alone. The 鎖定答案 slot holds two side-by-side 72px buttons: 重答 (`--ok`, hint 下一輪再挑一次) and 逃跑 (`--lav`, hint 換一題簡單的). On the team's next turn after 重答 the list is live again, with every eliminated option shown as that grey ✕ 答錯 tile and not pickable.
- **D8. TV beat and correct reveal (`tv-F1.png`, `tv-F2.png`).** During the beat the locked tile turns `--turn` with a 4px `--turn2` outline (2px offset) and a 17px "🔒 {隊名}" label; the dialogue box shows the fixed line {隊名}鎖定了 {letter}…… (local text, not an LLM call). On the correct reveal the correct tile turns `--ok` with a 4px white outline and a "✓ 正解" label; the other three turn opaque grey (`--cream2` face, `--dim-ink` text, `--dim-line` outline and letter chip; no opacity, so the wall never shows through); the dialogue box then plays the existing correct-answer narration.
- **D9. TV wrong reveal, state ⑤ (`tv-WA.png`, retry turn `tv-R.png`).** After the D10 beat, only the picked tile changes: `--danger` face, white text, `--wrong` bevel, 17px "✕ {隊名}答錯" label. The other three tiles stay as they were, so nothing hints at the answer. The dialogue box shows the fixed line {隊名}答錯了！他們正在決定：重答，還是逃跑…… until the choice arrives. On any later turn that shows the same question, every eliminated option is the grey "✕ 答錯" tile (D8 grey with a `--wrong` label), matching the phone.
- **D10. Reveal timing.** Beat: 2 s from the moment a client receives the lock's outcome to showing it, for **both** outcomes: a beat only before correct answers would itself give the answer away. `/screen` (D8 ①, then D8 ② or D9), `/play` (D5, then D14 or D7) and the `/host` status line (D3: {隊名}鎖定了 {letter}… then the result) all run the same beat. Correct reveal: auto-advance 8 s after the tile lights up, so 10 s after the reveal reaches the server. If the dungeon master's voice (TTS) is still speaking at that point, wait until it finishes, capped at 15 s after light-up. 下一題 on `/host` skips all of this at any time. How the room learns that speech is still running (a `/screen` report or an estimate from line length) is for /plan-eng-review; the 15 s cap holds either way.
- **D11. When the host's stuck-team buttons appear.** The 隊伍卡住時： row from D3 is hidden at first. It appears when the team on turn has done nothing for 15 s: 15 s after its MC turn starts with no confirmed lock, or 15 s after a wrong lock with no 重答 / 逃跑 choice. When it appears, a 14px line under the status box reads {隊名}好像卡住了. The clock is local to `/host` and restarts whenever the turn, the question or the pending wrong answer changes; a lock or a choice hides the row again. The buttons stay visible once shown, even while the team is still choosing, because a slow team is still a team the host may need to help.
- **D12. New color tokens.** Add to `app/globals.css` `:root` and the DESIGN.md color table: `--dim-ink: #8a7a8f` (text on an eliminated or faded option), `--dim-line: #7a6a80` (its outline and letter chip), `--wrong: #c94848` (the ✕ 答錯 label and the wrong tile's bevel). D5–D9 use these names. Eliminated and faded options are opaque `--cream2` tiles with these tokens, never `opacity` (so not `.px-btn:disabled`).
- **D13. Host keyboard on an MC turn (`lib/host-keys.ts`).** `2` maps to 替{隊名}選・重答 and `3` to 替{隊名}選・逃跑, under the existing rule that a key works only while its button can be pressed, so neither does anything before D11 shows the row. `1` does nothing on an MC turn until the correct reveal, when `1` or Enter is 下一題 as today. The two 48px buttons carry the same small 2 / 3 hints as the judge buttons (`aria-hidden`, pointer devices only).
- **D14. Phone on a correct reveal (`okphone-A.png`).** `/play` runs the same 2 s beat as `/screen` from the moment it receives the reveal, then the locked tile turns `--ok` with a "✓ 答對" label, the other tiles stay D5 grey, and the bottom bar becomes a `--ok` bar reading 答對了！＋{points} 分 (points = the question's difficulty, as awarded). It stays until the next question. The phone never shows the result before its own beat ends; the two clocks may differ by network delay.

### Journey storyboard (one MC turn)

```
STEP | WHO / WHERE            | USER DOES / SEES                                  | USER FEELS          | SPECIFIED BY
-----|------------------------|---------------------------------------------------|---------------------|-------------
1    | turn team, /play       | 4 options + 鎖定答案, picks one (◀ 已選)           | pressure, debate    | D2
2    | turn team, /play       | presses 鎖定, sees 鎖定中… instantly               | commitment          | D6
3    | everyone, /screen      | locked tile glows, 地城主: 紅隊鎖定了 B……          | suspense (2 s)      | D8 ①, D10
4a   | everyone, /screen+play | correct: green ✓ 正解, others grey; phone ＋N 分   | relief, cheering    | D8 ②, D14
5a   | everyone               | narration plays, auto-advance 8 s (waits for TTS) | payoff, no dead air | D10
4b   | everyone, /screen      | wrong: only their tile red ✕ 紅隊答錯; no answer  | groan, curiosity    | D9
5b   | turn team, /play       | 答錯了！要怎麼辦？ 重答 / 逃跑                      | agency              | D7
6b   | host, /host            | after 15 s idle: 紅隊好像卡住了 + 替選 buttons     | in control, calm    | D3, D11, D13
7b   | turn team, next turn   | same list, B greyed ✕ 答錯, not pickable           | second chance       | D7, D9 ④
```

5-second read: the TV tile states (gold, green, red, grey) carry the whole story from across the room. 5-minute read: every state has a text label, so nobody asks the host what happened. Over a full round: the host never judges an MC turn and can play.

### Interaction states

```
FEATURE              | IN FLIGHT               | IDLE / EMPTY                    | ERROR                          | SUCCESS                 | PARTIAL
---------------------|-------------------------|---------------------------------|--------------------------------|-------------------------|---------------------------
Phone lock (/play)   | 鎖定中… (D6)            | 鎖定答案 off until a pick (PR1) | 3 s no STATE: 沒送出，再按一次  | 🔒 已鎖定 (D5)          | retry turn: ✕ 答錯 tiles (D7)
Phone result         | beat 2 s, stays D5      | n/a                             | n/a                            | ✓ 答對 ＋N 分 (D14)     | wrong: 重答 / 逃跑 (D7)
TV tiles (/screen)   | beat: gold 🔒 隊名 (D8) | 4 cream tiles (D1)              | n/a                            | green ✓ 正解 (D8)       | red ✕ 隊名答錯 / grey (D9)
Host (/host)         | 鎖定了 {letter}… (D3)   | 等{隊名}鎖定答案… (D3)          | disconnect: existing 2D rule   | 答對！ + 下一題 (D3)    | 15 s idle: stuck row (D11)
```

Disconnects keep the existing rule (design review 2D, 2026-09): only `/host` shows a disconnect state; a phone that drops mid-lock falls back to D6's 3 s retry line.
