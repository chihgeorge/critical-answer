站長 2026-11-08 的決定，建立在 [boss-buzzer.md](boss-buzzer.md) 與 [boss-music-buzzer.md](boss-music-buzzer.md) 之上。

Status: APPROVED（F1–F8 由站長決定，細節由實作 lane 依現有做法決定）
活動：2026-11-21，功能截止 2026-11-18

> e2e 只在 GitHub CI 跑，不要在本機跑 `npm run e2e`（見 CLAUDE.md, Testing）。

一首歌常常要問兩三件事：歌名、歌手、出自哪部作品。這份文件讓一題聽歌題有 2–3 個答案欄位，主持人一欄一欄判，答對幾欄就拿幾成的傷害與獎勵。

「聽歌題」＝搶答階段裡，內容是 YouTube 而且勾了「只放聲音」（`audioOnly`）的題目。只有聽歌題能有欄位。

## 決定

| # | 問題 | 決定 |
|---|---|---|
| F1 | 題庫 | 填空題多一個選填的 `fields: {label, answer}[]`，2–3 欄。只有聽歌題能有，其他地方（一般題庫、不是搶答的首領階段、不是聽歌的題目）在讀題庫時就擋掉。`answer` 照樣存在，等於各欄答案用「／」接起來，所以原本讀 `answer` 的地方（主持人看答案、揭曉、旁白防洩題）都不用改。 |

## 實作

- **題庫**（`lib/question-bank.ts`）：`fields` 只掛在 `kind: "text"`。`parseTextQuestion` 讀欄位時，`answer` 由欄位接起來（JSON 裡的 `answer` 可省略，有寫也會被覆蓋）。`parseBank` 再檢查位置：一般題庫、不是搶答的階段、不是聽歌的題目，有欄位就報錯。`isMusicQuestion`、`fieldsAnswer` 給編輯器和房間共用。
（照 review 後的 D2–D6、E1–E6 實作。）

- **計分**（`answerQuestion`，`lib/game-state.ts`）：多一個參數 `fields: { right, total }`。首領命中：
  - 傷害：每答對一欄 1 格血（`right × 偷襲倍數 + 爆擊`；搶答階段沒有偷襲也不擲爆擊骰，所以就是 `right` 格）。
  - 獎勵：`Math.round((命中獎勵 + 爆擊／祝福加成) × right ÷ total)`，再算廚師 15%。四捨五入用 `Math.round`（0.5 進位），跟這個檔案其他地方一樣。打倒首領的 4d20 不打折（E1）。
- **協定**（`lib/protocol.ts`）：
  - `HOST_JUDGE` 多一個選填的 `fields: boolean[]`（每欄對不對）。有給的話 `correct` 必須等於「至少一欄對」。沒給（舊主持人頁）＝全對或全錯。
  - `TEAM_SUBMIT_TEXT` 多一個選填的 `fields: string[]`（每欄打的字，可空白）。
  - `PublicQuestion.fields`：各欄名稱（不含答案），手機和主持人頁用來畫格子和判定列。
  - `AnswerReveal.fields`：`{ teamId, marks: [{ label, answer, right }] }`，大螢幕畫揭曉和部分對那一行。
  - 打的字只給主持人（E4）：搶答階段的 STATE 把每隊的 `typedAnswer` 換成 `""`（只表示「送出了」，給那隊自己的手機看），拿掉 `typedFields`；真正的字放在只送主持人的 `HOST_ANSWER.typed`。一般回合的打字照舊（大螢幕本來就會顯示）。
- **房間**（`lib/room/dungeon-room.ts`）：收到 `HOST_JUDGE` 先檢查 `fields` 長度跟題目一樣，再把對了幾欄傳給 `answerQuestion`；擊殺要先擲 4d20 時，判定跟著 `pendingKill` 一起留著。
- **改判**（E2）：有欄位的題目按「↩ 重新逐欄判定」，房間回到那次答錯之前（這隊又握著搶答權，音樂暫停），不自動判；主持人頁重新出現逐欄判定。
- **血條**（E5）：`MAX_BOSS_HP` 60。大螢幕的心一顆 25 px，20 顆就 500 px，60 顆放不下 1280 px 的名牌，所以超過 20 格時改成一條 300 px 的血條加「剩下/總共」數字；20 格以下照舊畫心。

## 題庫資料格式

```json
{
  "kind": "text",
  "id": "song-1",
  "content": { "kind": "youtube", "value": "<videoId>", "audioOnly": true, "start": 5, "end": 20 },
  "answer": "晴天／周杰倫",
  "fields": [
    { "label": "歌名", "answer": "晴天" },
    { "label": "歌手", "answer": "周杰倫" }
  ]
}
```

讀檔時 `answer` 一律由 `fields` 重算，手寫 JSON 可以不填。名稱、答案都會去掉前後空白，不能空白。

## 各畫面

草圖：`[owner-local]/designs/multi-field-20261108/` 的 `phone.png`、`host.png`、`screen.png`、`editor.png`（本機檔，不進 git）。

- **手機**（`TextAnswerPanel`，`buzzed`）：每欄一個有標籤的輸入框，placeholder「選填，可空白」。有一格有字「送出」才亮。送出後顯示「已送出：晴天／—・等主持人判」。沒搶到的隊伍看不到這些框（照 #182）。
- **主持人頁**：搶到後，答對／答錯兩顆鈕換成逐欄判定（`components/field-judge.tsx`）：每欄一列「名稱：隊伍打的字 [✓] [✗]」，下面「送出判定」，文字跟著變（還沒標完／全對／對 1/2／全錯）。答案區照舊顯示「晴天／周杰倫」。
- **大螢幕**：揭曉時，原本「正解：…」那一行換成每欄一列「✓ 歌名：晴天」「✗ 歌手：周杰倫」（沒答對的淡一點）。標記留在題目卡裡，不碰左邊首領名牌和下方旁白框（1280×720 時那兩塊會蓋住「下一題：{類別}」）。
- **編輯器**：搶答階段的聽歌題，答案框旁多一顆「+ 加答案欄位」（變成 2 欄，第一欄帶入原本的答案）；有欄位時改成每欄「名稱＋答案」，可「+ 再加一欄」（最多 3）或「移除欄位」（回到單一答案）。

## 邊界情況

- 搶到的隊伍斷線：搶答權和打的字（`typedAnswer`、`typedFields`）一起清掉（照 M2）。
- 全部答錯後同一首重開（M1）：逐欄判定的標記重設（元件跟著 eventId 重新掛載）。
- 部分對而且剛好打倒首領：先擲 4d20（kill-roll.md），比例跟著 `pendingKill` 留到骰完。
- 舊手機（沒更新的頁面）送沒有 `fields` 的 `TEAM_SUBMIT_TEXT`：房間回 `fields_mismatch`，隊伍改用講的。
- 主持人送的 `fields` 長度跟題目不同（例如題庫剛改）：房間回 `fields_mismatch`，不判。

## 待決問題（給 /plan-design-review、/plan-eng-review）

1. **傷害怎麼四捨五入？** 建議：`Math.round`（目前做法，3 欄對 1 欄＝0 格血）。另一個選項：部分對至少 1 格血（`Math.max(1, …)`），那 2 欄對 1 欄跟全對一樣傷害。
2. **打倒首領的 4d20 要不要也乘比例？** 建議：不乘（最後一擊就是最後一擊）。
3. **全空也能送嗎？** 建議：不行，至少一格有字（全空等於沒打，用講的就好）。
4. **鍵盤快捷鍵在有欄位的題目上？** 建議：答對＝全對、答錯＝全錯（目前做法）。另一個選項：有欄位時快捷鍵停用，只能用畫面上的逐欄按鈕。
5. **「改判答對」在有欄位的題目上？** 建議：改成全對（目前做法）。
6. **欄位名稱上限？** 建議：10 個字。
7. **聽歌題不再是聽歌題（關掉搶答或只放聲音）時，欄位怎麼辦？** 建議：留著，存檔時擋下並說明原因。另一個選項：存檔時自動丟掉欄位、`answer` 保留接起來的字串。
8. **旁白要不要說「對了幾欄」？** 建議：不說，照用答對台詞（省改 narration、LLM prompt）。
9. **大螢幕要不要多一行「乙隊 對 1/2：傷害、獎勵各拿一半」？** 建議：要，部分對時才顯示，全對不顯示（草圖有畫；review 後已實作，見 D5）。
10. **手機揭曉的「正解：…」要不要也逐欄標 ✓／✗？** 建議：不用，手機照舊顯示「正解：晴天／周杰倫」，標記看大螢幕。

## 實作時自己決定的事

- 欄位名稱最多 10 個字（手機上是輸入框的標籤），答案不限長度（跟一般填空題一樣）。
- 欄位答案用全形「／」接成 `answer`。
- 隊伍打字：至少一格有字才能送（全空就不用送，直接用講的）；每格的清理規則跟一般打字一樣（最多 40 字）。主持人頁的「隊伍打字」把空格顯示成「—」；手機在搶答階段只看到「已送出」（E4）。
- 舊版主持人頁送沒有 `fields` 的 HOST_JUDGE：答對＝全對、答錯＝全錯（新主持人頁的快捷鍵在這種題目上停用，D4）。
- 大螢幕部分對那一行的「獎勵拿 {比例}」寫成百分比（`Math.round(k ÷ n × 100)%`），避免跟前面的 k/n 重複。
- 編輯器裡把題目改成不是聽歌題、或關掉搶答階段時，欄位還留著，存檔會被擋下並說明原因（跟 #182 的類別不同：類別留著無害，欄位留著會讓題目無法在一般回合判定）。
- 旁白不另外說「對了幾欄」：照用答對的台詞。
- 階段血量超過 20、但沒有答案欄位的題庫，照舊存成格式 6 以下（/ship review 想過改成 7 又改回來）：格式 6 的程式只在存檔時檢查血量上限，讀得進來也照常能玩，只是要先把血量調回 20 以下才能存；升成 7 反而會讓回滾後整份題庫變唯讀、改用預設題庫。

## 不做

- 自動比對打字答案。
- 一般房間或非聽歌題的多欄位。
- 每欄不同的分數權重。
