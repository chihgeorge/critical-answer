# 記憶題（先看再出題）

狀態：站長確認需求和 mockup（2026-11-12，Captain 轉達），已實作。
活動：2026-11-21，功能截止 2026-11-18。

## 要做什麼

題目可以標成「記憶題」。題目的影片、聲音或圖片播放時，題目藏起來：大螢幕和手機都不顯示題幹、選項、排序項目或欄位名稱。播完才出題，作答倒數也從這時開始。播完後影片或圖片收起來，不能重播。

- 題型：填空題（含多欄位 `fields`）、選擇題、排序題都可以。
- 內容：YouTube、上傳影片、上傳聲音（大螢幕回報播完），以及圖片（題庫寫「顯示幾秒」，3–60 秒）。
- 首領搶答階段的搶答題可以是記憶題：播完前不能搶答，播完才開放。

## 題庫格式

每題多兩個選填欄位：

- `memory: true`：只能是 `true`，不要記憶題就刪掉這欄。
- `memorySeconds`：圖片記憶題一定要有，3–60 的整數；影片、聲音記憶題和一般題不能有。

記憶題的內容要是圖片、YouTube、影片或聲音（文字題本身就是題目，不能當記憶題），而且一定要有題幹：播完後大螢幕只剩題幹，沒有題幹就沒有題目。`parseBank` 讀題庫時檢查，每個錯誤訊息都寫出怎麼改（`memoryProblem`）。題庫用到記憶題時格式版本是 11（`MEMORY_FORMAT`），舊版程式不會讀到看不懂的題目。

## 房間怎麼做

- `currentQuestion()` 回傳的 `pub` 換成記憶題畫面（`memoryView`）：播放中只有內容和 `memorize: true`（圖片多一個剩幾毫秒的 `memoryLeft`），播完後內容換成題幹文字，選項、項目、欄位照舊。所有讀 `pub` 的地方（大螢幕、手機、作答倒數、抓包神諭、旁白下一隊）都自動看到這個畫面，不用各自判斷。
- 播完是每一題各自記：`memoryDone`（題目 id 清單）。只用一格的話，別隊的影片播完會把前一題的記憶題也打開。首領階段同一題大家一起看，所以一題播完就算全場播完。
- 影片和聲音：大螢幕送 `SCREEN_CLIP_ENDED` 時結束。上傳的影片和聲音在公開內容裡也是 `kind: "youtube"`，所以同一條路徑就涵蓋它們（測試釘住）。
- 圖片：題目第一次出現在畫面上時記下 `memoryShow { questionId, endsAt }`，到時間由計時器廣播一次狀態，`syncMemory()` 看到時間到就記成播完。圖片顯示後輪到別題（這隊手機斷線、逃跑、重開房間時別隊先連回來）時，截止時間照走：回來時只剩剩下的秒數，關掉手機不能多看一次，手機睡一下也不吃虧。同時只算一張圖：別題的圖片要開始時，前一張還在算的就當看過。重開房間時照牆上時間接著倒數。
- 主持人 `HOST_MEMORY_DONE { questionId }`（「⏭ 直接出題」）：大螢幕放不出來或主持人想提早出題時用。已經播完的題目再按什麼都不做；不是正在記憶中的題目會被拒絕（`stale_question`）。
- 記憶中時拒絕手機的選選項、鎖定、送出填空、職業技能、搶答（`memorizing`）；抓包和神諭也關著。幸運藥水照常可以喝（不透露題目）。
- 作答倒數在記憶中等著（`left: null`），播完才開始數。
- 說服檢定在記憶之前：先擲檢定，再看內容，再出題（和「先檢定再出題」一致，內容也算題目的一部分）。
- 主持人頁收到的 `HOST_ANSWER` 在記憶中帶完整題目，主持人看得到題幹和答案。
- 記憶中判定時，揭曉帶 `asked`（完整題目），所以答案畫面會再出現圖片；影片在揭曉時照原本規則重播。
- 改判、修正、復原不讀記憶狀態，不受影響。

## 畫面

- 大螢幕：題目那一行換成「🧠 {隊名}的記憶題：看仔細，播完才出題」（聲音是「仔細聽」，圖片是「記住這張圖！」加剩幾秒；主持人還沒按 ▶ 時是「等主持人播放…」，搶答階段不寫隊名）。播完後只剩文字題目。
- 手機：一個「🧠 記憶題」面板：「👀 看大螢幕，記住內容」（聲音是「👂 仔細聽大螢幕」）和「題目等一下才出來，還不能作答」。手機不顯示記憶題的圖片，免得截圖。
- 主持人頁：記憶中一直顯示「⏭ 直接出題」；大螢幕回報放不出來時寫「大螢幕放不出來：現場放一次或講一下內容，再按「⏭ 直接出題」」。作答倒數寫「⏱ 記憶完後開始倒數」。記憶中 ▶ ⏸ ⟲ 照常可以用，播完就不能重播。
- 題庫編輯：內容是圖片、YouTube、影片或聲音時出現「🧠 記憶題（先看再出題）」勾選框；圖片多一格「顯示幾秒」（預設 10）。內容換成文字時兩個欄位一起拿掉。YouTube 沒填結束秒數時提醒；上傳的影片和聲音會整支播完。
- 題庫健檢：記憶題的 YouTube 沒設結束秒數列成黃色（整支播完才出題）。

## 決定（自動決定的品味選擇）

- 沒有切換音效（先記在 TODOS）。
- 圖片倒數從題目出現在畫面上開始，不等圖片載入完。
- 手機不顯示記憶題圖片。
- 先檢定再看。
- 揭曉時再顯示一次記憶內容。
- 圖片網址還是在狀態裡送到手機，只靠畫面藏起來：接受這個風險（有心人打開開發者工具才看得到，影片本來就一樣）。
- 旁白不變：旁白只講隊伍和怪物，畫面上的橫條就是提示。
- 協定命名：`memorize`（記憶中）、`memoryLeft`（毫秒）。

## 已知限制

- 記憶中重開房間：圖片照時間接著數；影片要主持人再按一次 ▶（媒體指令本來就只在記憶體裡）。
- 大螢幕沒有接上（沒有 `screenKey` 的大螢幕不回報播完）時，影片不會自己結束，要主持人按 ⏭。
- 圖片網址和影片 id 在狀態裡，只靠畫面藏。
- 圖片的秒數在伺服器算，不等大螢幕連上或圖片載入：大螢幕剛好斷線時可能看不到，主持人可以現場講一下。大螢幕自己的橫幅（首領警報、最後衝刺、抓包）蓋住圖片時秒數也照走；首領房第一題不要放很短的圖片記憶題。
- 播完是全場記一次：一隊逃跑後同一題之後再發給別隊時，直接出文字題，不再播一次（大家當時都在大螢幕看過）。復原不會讓記憶題重播。
- 主持人在記憶中也可以判定（例如隊伍口頭先答），揭曉照常帶完整題目。判定不會結束記憶（判定可能失敗，首領搶答階段也要靠播完才開放搶答）：答錯下輪再答時題目還在記憶中，就按 ⏭。
- 有兩台大螢幕時，先播完的那台回報就出題，慢的那台影片會被收起來。
