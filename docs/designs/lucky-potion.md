# Design: 🧪 Lucky potion, a one-use team item the host hands out

Generated by /office-hours on 2026-11-08
Branch: main
Repo: chihgeorge/critical-answer
Status: APPROVED
Mode: Builder

## Problem Statement

Most questions are quiz or multiple-choice questions, so teams rarely get a chance to "perform", and the host has no in-game way to reward a team that warms up the room (a funny wrong answer, loud cheering, a good team chant). We want a small, visible reward the host can hand out at any time, which the team then chooses when to spend.

## What Makes This Cool

- The host shouts "這隊，幸運藥水！" and the whole room sees a 🧪 appear on that team's map pawn.
- The team decides when to drink it. Holding it is a little strategic: "save it for the boss, or use it now?"
- When it pays off, the big screen rolls two d20s at once; the higher one glows. A natural 1 rescued by an 18 gets a cheer.

## Constraints

- Ship by 2026-11-18; the event is on 2026-11-21. No deploys during the event.
- The five classes must stay balanced. A warrior already rolls a d20 for the answer itself (`kind: "warrior"`), so advantage on that roll would make warriors far too strong.
- Phone, host and big-screen pages must not import the parsed `BANK` (CLAUDE.md). This feature touches no bank data.
- Big-screen art follows DESIGN.md: 960×540 stage, Cubic 11 and Press Start 2P, two-frame `steps()` motion.

## Premises (agreed)

1. **Host gives it freely.** No fixed trigger: the host presses 「🧪 給藥水」 for any team at any time, even off-turn. The narrator says one line of praise.
2. **One use, the team chooses when.** The team drinks it on its own turn from the phone.
3. **Effect: the next die this question rolls twice, keep the higher.** It applies only to the dice every class has: the crit die (`kind: "crit"`) and the persuasion check (`kind: "check"`). It never applies to the warrior's answer die or the boss kill roll.
4. **At most one potion per team.** While a team holds one, the host's button for that team is greyed out as 「🧪 已有藥水」. Once drunk, the host can give another.
5. **No roll, no cost.** If the team drank it but this question rolled no die (wrong answer, escape), the potion goes back to the team. It is used up only when a die actually rolls with it.
6. **Name: 🧪 幸運藥水.** A classic RPG consumable; "drink it and it's gone" makes the one-use rule obvious.

Ruled out during the session: auto-trigger rules (overlap with 最後衝刺); a re-roll after the die lands (needs the 2-second roll beat to become interruptible); "this wrong answer doesn't count" (overlaps the cleric's prayer); making every class skill dice-based before the event (1–2 days, see Next Steps).

## Approaches Considered

### Approach A: Minimal
Two fields per team (holds a potion, drank it this question), scripted narrator line, a two-dice roll overlay. About 2 hours.

### Approach B: General team inventory (chosen)
Each team gets an item slot that 最後衝刺 and later items can reuse. About 3–4 hours.

## Recommended Approach

Approach B, with big-screen option A (both dice roll together).

- **State.** Add an item slot to the team state in `lib/game-state.ts`: `item?: "luckyPotion"` plus `itemArmedFor?: string`, the question id it was drunk on (eng review E1). Keep it separate from `boon` (event-rooms.md D12): a boon is applied automatically on the next correct answer, an item is spent by the team.
- **Messages** (`lib/protocol.ts`):
  - host → room: give the potion to a team. Refused if the team already holds an item.
  - team → room: drink it. Accepted only on the team's own turn while it holds one and has not drunk it yet.
  - The public room snapshot carries each team's item and armed flag, so all three screens render from it.
- **Roll** (`lib/room/dungeon-room.ts`, `startRoll`): for `kind` `"crit"` or `"check"`, if the team's potion is armed for this question, roll two d20s, set `values: [a, b]` and `value: max(a, b)`, and clear `item` and `itemArmedFor` in the same STATE (E3). A question that ends without a roll keeps the item (premise 5, E2). `fixedDie` (test hook) fixes both dice.
- **Host page** (`app/room/[code]/host/page.tsx`), see D3: each team row gets a 44px `PixelButton` 「🧪 給藥水」 just before 「交給新手機」, greyed (`disabled`) as 「🧪 已有」 while the team holds one.
- **Phone** (`app/room/[code]/play/page.tsx`), see D2, D4–D6.
- **Big screen** (`app/room/[code]/screen/page.tsx`, `components/map-strip.tsx`, `components/d20.tsx`), see D1, D7, D8, D10, D11.
- **Narration.** One scripted line when the host gives a potion (D7). No AI call, so it works without an AI key.

### Design review decisions (/plan-design-review, 2026-11-08)

- **D1 Who holds one, on the big screen.** A 12px 🧪 sits on the top-right corner of the team's map pawn tag (D11). While a holding team is on turn, the question panel's top row adds a `LabelChip` 「🧪 有幸運藥水」, placed and styled like the event boon chip (`screen-boon`). No new nameplate row: the stage has none during play.
- **D2 Phone placement.** The team card (`/play`, the panel with the class line) adds the line 「🧪 有一瓶幸運藥水」 under the class line, styled like the `phone-boon` line, on or off turn. On its own turn, the drink button sits directly above the control it affects: 「鎖定答案」 (multipleChoice/sort crit) or 「擲說服檢定」 (fill-in check).
- **D3 Host placement.** In the team row (see Host page above). The row already wraps (`flex-wrap`).
- **D4 No undo.** One tap drinks it. The button is replaced by the team-card line 「🧪 已喝下：這題的下一顆骰擲兩次取高」 on `--lav`. A mis-tap only spends it on a die the team was about to roll anyway.
- **D5 Returned potion.** When the question ends with no roll, the team-card line reads 「🧪 藥水還在：這題沒擲到骰」 until the team's next question starts, then 「🧪 有一瓶幸運藥水」 again. Screen and narrator say nothing.
- **D6 When the drink button shows.** Only on the team's own turn, only while a crit or check roll can still happen on this question: not in an event room, not in a boss buzzer phase, not after the lock is in or the check is rolled, not when already drunk. Otherwise it is absent, not greyed. The room refuses a drink in the same cases.
- **D7 The give moment.** The owl's `DialogueBox` reads the scripted line 「🧪 {隊名}拿到一瓶幸運藥水！」 after the line it is reading. At the same STATE the pawn's 🧪 appears. Nothing covers the question.
- **D8 The drink moment.** The question panel's chip changes to 「🧪 已喝下！」. No narrator line (the roll's own line follows).
- **D9 Colors.** No new token. Both buttons use the default `PixelButton` (retry, `--warn`), told apart by 🧪. The drink button is 56px tall and full width, so it reads as secondary to the 78px `ok` lock button below it.
- **D10 Two dice.** Extend `RollOverlay` (the 2 s crit/check roll) with an optional second value: two dice side by side, tumbling and landing together. The higher die has a `--turn` face; the lower one has a `--dim-line` outline and `--dim-ink` digits. The chip above them reads 「🧪 幸運藥水！擲兩次取高」. The result line keeps its current wording, computed from the higher die, after 「取高：{n}」. A tie shows both as higher. Reduced motion shows both values at once, as `RollOverlay` does now. `KillRollOverlay` is not used.
- **D11 Pawn mark.** See D1. It does not change the tag's width, so eight pawns in one room fit as before.

## Eng review (2026-11-08, done by hand)

`/autoplan` could not run: its guard hook refused the phase entry (`init_required`) after two successful snapshot inits, before and after a gstack upgrade. This review read the code directly.

### What the code already does

- `startRoll` (`lib/room/dungeon-room.ts`) is the one place every d20 is rolled. Crit dice come only from a correct `multipleChoice`/`sort` lock (`handleTeamLockOption` → `startRoll("crit")`). Persuasion checks come only from `TEAM_ROLL_CHECK` on a `text` question. A host-judged fill-in answer rolls no crit die.
- A warrior's ability roll (`kind: "warrior"`) on a multipleChoice question is the crit die too (`judge` comment). Premise 3 keeps the potion off it, so a warrior who drinks and then uses the ability on that question gets the potion back (no crit/check roll happened).
- `sneakArmed` is the closest existing pattern: a per-team "armed for this question" flag, cleared in `answerQuestion`, refunded in `sendToBoss` and at a buzzer phase. Each of those sites had to remember it. E1 avoids that.
- `resolveRoll` drops a roll whose turn moved on during the beat, and "the use stays spent" (warrior R3). E3 follows the same rule.
- `getSpectatorView` (`lib/game-state.ts`) copies `sneakArmed` and `boon` into the public team view; `item` and `itemArmedFor` go the same way.
- Narration: `handleEditNarration` rewrites a line of `lastNarration` and rebroadcasts `NARRATION` with the same `eventId` and `rev + 1`; the screen's `DialogueBox` reads a new line under the same id when its turn comes (host-narration-edit.md D13). E5 appends with the same mechanism.

### Decisions

- **E1 Armed state is a question id.** `itemArmedFor?: string`. The potion is armed only while `itemArmedFor === currentQuestionIdOf(game, teamId)`. When the team leaves the question by any path (answer, flee, sent to the boss, buzzer phase, event room), the id no longer matches and the potion is simply held again. No clearing code at each exit. Rejected: a boolean like `sneakArmed`, which needs a reset at every exit. (Implementation /review, 2026-11-08: the arm also records the team's `turns` as `itemArmedTurn`, so a 重答 on the same question next round, or the same id dealt again later, finds the potion held, not armed. The public view carries the result as `itemArmed`.)
- **E2 Returned-potion text (D5).** The phone shows 「🧪 藥水還在：這題沒擲到骰」 while `itemArmedFor` is set, does not match the current question, and it is not the team's turn. On its next turn the normal 「🧪 有一瓶幸運藥水」 shows. This is D5's "until the next question starts" with no extra state. `itemArmedFor` is overwritten by the next drink.
- **E3 Spent at the roll.** `startRoll` clears `item` and `itemArmedFor` in `this.game` before it broadcasts, so a restart mid-beat cannot hand the potion back and roll again. A roll dropped in its beat keeps it spent (warrior R3).
- **E4 Room checks.**
  - `HOST_GIVE_ITEM { teamId }`: host only; `phase === "playing"`; team exists; team holds no item. Otherwise `invalid_action` (`item_held`, `not_playing`).
  - `TEAM_DRINK_POTION { questionId, eventId }`: stale `eventId` → `stale_event`. Not the team's turn, paused, `pendingLock`/`pendingRoll`/`pendingWrong` → refused. No item → `no_item`. Already armed for this question → `already_drunk`.
  - D6 cases are refused too: event room, buzzer phase, check already rolled on a `text` question, question kind `sort`/`multipleChoice` with a lock already in.
  - The phone computes D6's "button shows" from the same STATE fields, so a refusal only happens on a race.
- **E5 Give line.** The owl line is appended to `lastNarration.lines` when that narration belongs to the current `eventId`, rebroadcast with `rev + 1`. If the current event's narration has not arrived yet (AI still writing), the room keeps the line and appends it when that narration lands (user decision, 2026-11-08). The line is capped with `sanitizeText(…, MAX_EDIT_LINE)` because team names are user text. A held line is dropped if the game finishes first (same rule as `dropUnsaidLine`).
- **E6 Two dice on the wire.** `PendingRoll.values` (today only for `kill`) carries `[a, b]` on a potion crit/check. The screen keeps choosing `KillRollOverlay` only for `kind === "kill"`, and passes `values` to `RollOverlay` otherwise (D10). `value` stays the kept die, so `resolveRoll`, `recordCheck` and the natural-20/natural-1 rules need no change.
- **E7 Logging.** The roll's existing JSON log line already prints `values` when present; potion rolls get it for free.

### Architecture

```
host page ──HOST_GIVE_ITEM──▶ DungeonRoom.handleHostGiveItem ──giveItem(game)──▶ team.item
                                         └─▶ appendGiveLine (now, or when narration lands)
phone ──TEAM_DRINK_POTION──▶ handleTeamDrinkPotion ──drinkPotion(game)──▶ team.itemArmedFor = questionId
lock correct / TEAM_ROLL_CHECK ──▶ startRoll(kind)
        armed for this question && kind ∈ {crit, check}?
          yes: a,b = d20,d20 → pendingRoll{value:max, values:[a,b]}; game = spendPotion(game)
          no:  one d20 (unchanged)
STATE ──getSpectatorView──▶ team.item / team.itemArmedFor ──▶ host row, phone card, screen chip + pawn
```
