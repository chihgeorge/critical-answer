## Problem Statement

TODOS.md 有兩條：「每回合能選不同行動，不只答題」和「每隊有職業，戰鬥時有特殊能力」。現在每回合只能答題。答錯就失去這回合，要等其他隊伍都輪完一圈。不會的題目沒有別的辦法。

## What Makes This Cool

- 不會的題目也有機會。戰士擲 1d20，12 以上就算答對，TV 上大家一起看骰子。
- 每隊的玩法不一樣。四個職業各有一個能力，所以帶朋友玩時，每隊會想不同的策略。
- 能力只幫自己，不害別人。朋友之間的競爭保持友善。

## Constraints

- 目標是好玩、帶朋友玩，不是商業產品。
- 伺服器說了算：輪次、剩餘次數、能力能不能用，都在 Durable Object（`lib/game-state.ts`）裡檢查。
- 只有 server-only 的檔案可以 import BANK。法師要刪掉錯的選項、盜賊要看答案第一個字，所以都要在伺服器算好，只把結果送給手機。`npm run check:bundle` 一定要過。
- 現有規則不變：答錯（重答或逃跑）都會換下一隊（`advanceTurn`），boss 房答錯會照現有條件換題（`newBossQuestion`）。例外是下面的牧師祈禱（保留回合）和戰士擲骰（不經過 `pendingWrong`）。

## Premises

1. 職業能力就是那個「另一個行動」。輪到你時，手機上除了答題，多一個職業能力按鈕。不另外做行動清單，一個設計解決兩條 TODO。
2. 能力只幫自己隊伍。
3. 在大廳用手機選職業。遊戲開始後鎖定。可以重複選同一職業，也可以不選（普通冒險者）。
4. 四個職業，每個一場只能用 2 次：
   - 法師：刪掉 2 個錯的選項，只能用在選擇題。
   - 牧師（祈禱）：答錯後用。保留回合，立刻再答一次：同一題（少一個錯的選項）重答，或馬上逃跑換一題簡單的。boss 房祈禱：題目照常換，這隊保留回合，馬上答新題（Eng Review R1、R1b）。一般隊伍答錯要等一整圈，這就是牧師的好處。
   - 戰士：擲 1d20 代替答題。12 以上算答對（全額獎勵、前進），11 以下算答錯。成功率 45%。
   - 盜賊：偷看答案的第一個字。用了之後答對只拿一半獎勵。
5. 戰士的骰子在 TV 上有動畫。TV 現在沒有骰子動畫（最後一擊的 4d20 只是一個數字），所以 PR 1 在 TV 頁面裡新畫一顆骰子（Eng Review Scope finding 1）。
6. 先不仔細平衡數字。帶朋友玩一場真的，再調整。

## Cross-Model Perspective

Codex 冷讀（沒看過這段對話）的重點：

- **最酷的版本**：每次用能力都變成全場的焦點。手機按下去，TV 播一段跟職業有關的動畫和音效，再顯示結果。等待中的隊伍也有東西看。
- **High**：戰士 12 以上是 9/20 = 45%，比四選一亂猜（25%）高。建議先玩一場再決定要不要改門檻。使用者決定維持 12。
- **Medium**：牧師在 boss 房要有清楚的規則。祈禱後保留回合、題目不換，下一隊看到什麼要寫清楚。
- **Medium**：盜賊的「第一個字」要定義。口說題、數字、標點、圖片題，第一個字可能洩題太多，也可能沒用。
- **Low**：現有的「戰鬥 / 討價」分支選擇（`BRANCH_OPTIONS`，`lib/game-state.ts:57`）還顯示在手機上，但不影響任何事。職業能力上線時，移除它或給它用途。
- **建議**：先做戰士一個職業，打通「大廳 → 手機 → 伺服器 → TV」整條路，再加另外三個。

## Approaches Considered

### Approach A: 先做戰士，打通整條路（已選）
戰士會碰到大廳選職業、次數限制、伺服器擲骰、TV 動畫。第一個 PR 只有戰士，第二個 PR 加法師、牧師、盜賊。

### Approach B: 四個職業一次做完
不選：PR 太大，牧師的「保留回合」會改到輪次邏輯，跟其他三個混在一起難審。

### Approach C: 先做法師和盜賊
不選：沒有 TV 動畫和輪次變化，最好玩的骰子和祈禱都還沒有。

## Recommended Approach

Approach A。兩個 PR：

**共通規則（兩個 PR 都適用）**
- 一隊一回合最多用一次能力，同一題最多一次。所以法師不能在同一題連用兩次，盜賊也不能偷看兩次。
- 伺服器在這些狀態才接受 `use-ability`：輪到這隊，有職業，剩餘次數 > 0。法師、盜賊、戰士只能在還沒鎖定答案、沒有 `pendingWrong` 的時候用。牧師只能在這隊自己的 `pendingWrong` 等待中用。
- 戰士用了就取代這次答題。法師和盜賊用了以後，這隊照常答題。

**PR 1：職業的基礎 + 戰士**
- `Team` 加 `classId?: "mage" | "cleric" | "warrior" | "thief"` 和 `abilityUses: number`（開始時是 2）。
- 舊 snapshot：不升 `SCHEMA_VERSION`。讀取時，沒有 `classId` 就當普通冒險者，沒有 `abilityUses` 就給 2。加兩個測試：舊格式的 snapshot 讀進來後，每隊都是 `classId` undefined、`abilityUses` 2，`use-ability` 被拒絕；有 `classId` 但沒有 `abilityUses` 的 snapshot 讀進來後是 2 次。預設值在 `lib/room/snapshot.ts` 的 `parseSnapshot` 裡補：隊伍沒有 `abilityUses` 就給 2；`pendingTeams` 的 `classId` 可以沒有。
- 大廳：手機上選職業，存在 `pendingTeams` 的那一隊上，遊戲開始時帶進 `Team`，之後鎖定。遊戲開始後才加入的隊伍沒有職業。這隊任何一支手機都能選，遊戲開始前最後一次選的算。主持人頁面顯示每隊的職業，但不能改。
- 新的 action `use-ability`，檢查見上面的共通規則。
- 擲骰有 2 秒懸念：伺服器先擲，廣播 `pendingRoll {teamId, questionId, value}`。TV 轉骰子，停在 value。2000 ms 後才判。等待時拒絕 HOST_JUDGE 和鎖定。輪次已經換了，就丟掉這次擲骰。次數在判的時候才扣，所以丟掉的擲骰不扣（Eng Review R2、R3）。
- 戰士成功（12 以上）：完全等於答對。揭曉答案（`AnswerReveal`），題目記進 `revealedQuestionIds`，加進度分（等於難度）和獎勵，前進到下一個房間。boss 房算一次命中（10 分、扣血）。打到最後一擊一樣擲 4d20。
- 戰士失敗（11 以下）：等於 `incorrect-retry`。不刪任何選項，換下一隊，這隊下次輪到時面對同一題。boss 房完全照現有的答錯重答規則（`lib/game-state.ts` 的 `fleeChoice === "flee" || shownWrong`）：這題的 `eliminated` 是空的就不換題；已經有被刪掉的選項（例如之前答錯的，或 PR 2 別隊法師刪的）就換題。加兩個測試：PR 1 boss 房戰士失敗、`eliminated` 是空的，題目不變；PR 2 先有法師刪選項，再戰士失敗，題目換掉。
- 口說題也能用戰士，伺服器直接判，主持人不用判。
- 匯出 `rollD20`（已經可以傳入 `rng`）。12/11 邊界的測試用固定的 `rng`。
- TV：在 TV 頁面裡新畫一顆骰子，轉完停在 `pendingRoll.value`，顯示結果。Codex 說的每個職業專屬動畫和音效不在這兩個 PR 的範圍。
- 「戰鬥 / 討價」分支選擇不在這次範圍，維持現狀。

**PR 2：法師、牧師、盜賊**
- 法師：只能用在選擇題。伺服器挑 min(2, 剩下的錯選項數 − 1) 個錯選項。結果是 0 就拒絕這次使用，不扣次數。刪掉的選項放進公開的 `eliminated`，所有畫面都看得到變灰，跟現在答錯的選項一樣。這不洩漏答案。boss 房的題目是大家共用的，所以法師刪的選項別隊也看得到，也等於幫到別隊。先接受這點，試玩後再看要不要改成只有這隊看得到。
- 牧師（祈禱）：只能用在選擇題，因為口說題答錯是主持人直接判重答或逃跑，沒有等待選擇的時間。在這隊的 `pendingWrong` 等待中按「祈禱」，扣一次。接著這隊選重答或逃跑，但不 `advanceTurn`，還是這隊的回合。boss 房：牧師隊還有次數時，答錯的鎖定不自動結算（不設 `armBossMiss`），手機顯示「祈禱 / 不用」。按祈禱：照現有規則換題，這隊保留回合，馬上答新題。按不用：照現在的 boss 答錯處理。隊伍卡住時，主持人用現有的卡住列 fallback 結算（Eng Review R1、R1b）。祈禱後再答錯，照一般規則處理（boss 房換題、換下一隊）。其他隊伍的畫面沿用現在的 boss 題目畫面（逃跑換題後就顯示新題目），只多一行「牧師祈禱中」。
- 盜賊：伺服器取答案的第一個字。選擇題取正確選項文字的第一個字，口說題取答案文字的第一個字。答案不是文字（只有圖片）就拒絕，不扣次數。提示不放進廣播的 state 或 `SpectatorView`。它只用私訊送給這隊的連線（`connTeam` 對到這隊的那些）。伺服器只記在記憶體（不進 snapshot），重連時再補送。已知限制：Durable Object 重啟後提示會不見，已扣的次數不還。這隊目前的題目 id 一變（答對、逃跑、boss 換題、進入 boss 階段）或遊戲結束，就清掉。加一個測試：其他隊和 TV 的連線收不到提示。
- 選擇題的正確選項第一個字常常只對得上一個選項，等於半價拿到答案。先接受（Premise 6），試玩後再看要不要只給口說題用。
- 盜賊的減半：只減那一題答對拿到的獎勵分，無條件捨去。boss 房那一下的命中獎勵（10 → 5）和最後一擊的 4d20 也一起減半。進度分和 boss 扣血不變。減半跟提示同時清掉：這隊目前的題目 id 一變或遊戲結束就失效。加一個測試：boss 房換題後，提示不再補送，下一題的獎勵不減半。

## Success Criteria

- 帶朋友玩一場，至少有兩隊選不同職業，每個職業至少用過一次。
- 戰士擲骰時，TV 前有人叫出聲。
- 沒有隊伍能在別人的回合用能力，也不能用超過 2 次（伺服器測試覆蓋）。
- `npm run check:bundle` 通過，答案沒有進到手機的 bundle。
