## Problem Statement
站長想讓 11/21 的派對問答更有真人 DnD 跑團的感覺。站長選了三個方向：
- 主持人像真 DM 一樣即興加料（音效、燈光）。
- 地城探索感：每間房有自己的氣氛，加上揭開迷霧的那一刻。
- 原話：「打王時要有緊張感的動畫」。

主持人就是站長本人，一邊判答案、按下一題，一邊加料（「我自己邊主持邊按」）。

## What Makes This Cool
真人 DM 要自己記得什麼時候切音樂、放音效。這個遊戲本來就知道每個節點：誰進房、輪到誰、還剩幾秒、王剩多少血、第幾階段。所以氣氛可以交給遊戲狀態自動指揮。主持人兩手都在忙，只留三顆大鈕給他即興。

王戰會像一段遊戲自己指揮的配樂：
- 王出手前先蓄力預告，全場一起屏息。
- 倒數時心跳越來越快。
- 王快死時先安靜半秒，再爆出暴走音樂。

## Constraints
- **時程與流程**：11/18 前上線，11/21 活動。每個 PR 都走 /autoplan → 實作 → /review → /ship → CI 綠 → 合併 → /canary。e2e 只在 CI 跑。
- **規則與題庫**：不改遊戲規則，也不改題庫格式（`BANK_FORMAT` 不動）。作答時間、出題時機、計分全部照舊，伺服器的計時不受影響。
- **聲音引擎**：聲音照現有做法用 WebAudio 合成（`lib/sfx.ts`、`lib/bgm.ts`、`lib/bgm-player.ts`），不加音檔，也不換音訊引擎。
  - 現況一：`duck()`／`mute()` 只控制音樂的 `master` 音量。`playCue()` 的效果音另外接一條 bus 直接通到喇叭，所以完全不受靜音影響。
  - 現況二：音樂沒在播時，`playCue()` 不出聲。
  - 這兩點 PR1 都要改（見 PR1 的聲音分層）。
- **瀏覽器限制**：頁面要先被點一下才能出聲。大螢幕的 🎵 和語音兩個開關分開存（`BGM_ENABLED_STORAGE`、`TTS_ENABLED_STORAGE`），預設都是關的。
- **安全**：答案和題庫不能進瀏覽器 bundle（`npm run check:bundle`）。新加的協定訊息要驗證是誰送的，並且在伺服器端限頻。
- **閃光安全**：整個大螢幕合計每秒不超過 3 次閃光（不是每個效果各算），不做全螢幕飽和紅色閃光，畫面震動不超過 8px。執行方式：大螢幕有一個共用的閃光預算。計算單位：一次閃光＝一次「亮起再暗下」的脈衝（一下心跳紅暈、一次雷聲白閃、一次反擊紅閃各算一次）。任意 1 秒內最多 3 次。預算滿時，後到的效果（不論是哪一種，包括心跳）改成只有聲音加靜態色調、不閃。心跳最快每秒 2.5 下，所以倒數最後階段心跳本身就會用掉大部分預算，這時按 ⚡ 雷聲只出雷聲和一層靜態淡白。`prefers-reduced-motion` 開啟時不閃也不震，改成音效加靜態變色。以上是 PR1、PR2 的驗收條件。

## Premises
1. **自動氣氛**：氣氛跟著遊戲狀態自動走。會自動觸發的時機有進房、王登場、倒數最後 5 秒、王低血、答錯。主持人只多三顆大鈕：雷聲、低吼、螢幕變暗。
2. **改動範圍**：會動的是大螢幕（畫面和聲音）、主持人頁，以及最少量的協定訊息和房間轉發。不改規則、不改題庫格式、不改計時。
   - 新增的訊息：PR0 一個（大螢幕回報聲音是否就緒），PR2 兩個（主持人效果、螢幕變暗狀態），見各 PR。
3. **地圖**：地圖已經有戰爭迷霧（`components/map-strip.tsx`），這次只加每間房的環境音和光線，以及揭霧的那一刻，不重做地圖。
4. **聲音**：全部由瀏覽器合成。每一層聲音在影片題、旁白、搶答暫停時各怎麼處理，照下面的「聲音分層表」。
5. **上線順序**：依影響大小一個一個 PR 上線，王戰最優先。每個 PR 都能單獨上線，來不及就停在前一個。
- **修正（Codex）**：「燈暗」按鈕叫「螢幕變暗」，只讓大螢幕變暗，控制不了場地的燈。
- **修正（站長）**：答錯時的動畫演「王格擋反擊」。不扣血、不加規則，因為「王打人不扣血有點奇怪」。

## Cross-Model Perspective
Codex（gpt-6-luna）冷讀重點：
- **最酷的版本**：王戰做成遊戲自己指揮的配樂。出手前先有預告音和蓄力，接著才是撲擊、震動、紅閃。倒數時心跳併進配樂。換階段時先靜音，再接更激烈的版本。
- **站長最在意的**：「打王時要有緊張感的動畫」，四個效果全選。
- **工具選擇**：可以參考 Tone.js 的分層和排程概念，但沿用現有的 WebAudio 引擎。
- **High**：要有明確的開場「點亮音效」步驟（PR0），不然當天可能整場沒聲音。
- **Medium**：效果疊在一起會搶注意力，要訂優先順序（見聲音分層表）。

## Approaches Considered
- **A：只做王戰**。沒選，因為站長三個方向都要。
- **C：王戰＋玩家手機一起紅閃**。沒選，因為 iPhone 網頁不能震動，而且沒有房間氛圍。
- **B：分三個 PR**。選這個，見 Recommended Approach。

## Recommended Approach
Approach B，分三個 PR 依序上線。草圖在 `~/.gstack/projects/chihgeorge-critical-answer/georgechih-claude-progress-check-703b40-sketch-20261112.png`（只在本機）。

### 聲音分層表（PR1 建好，PR2、PR3 沿用）
`lib/bgm-player.ts` 改成四層，各自有音量控制，最後都經過總音量：

| 層 | 內容 | 影片題播放中 | 搶答後暫停／主持人自己放歌 | 旁白說話中 |
|---|---|---|---|---|
| 音樂 | 地城主題、王戰暴走版 | 靜音 | 靜音（現況） | 變小聲（現況） |
| 王戰效果 | 心跳、蓄力、格擋反擊、登場低音 | 靜音（只剩畫面效果） | 靜音（只剩畫面效果） | 照常 |
| 主持人效果 | 雷聲、低吼 | 鈕變灰，不能按 | 照常，主持人自己決定 | 照常 |
| 環境音（PR3） | 滴水、風、營火 | 靜音 | 靜音 | 變小聲 |

- 效果音不必等音樂在播才會響，只要聲音已經解鎖就能播。
- 「已解鎖」是新的狀態：AudioContext 已經被使用者的點擊喚醒。
- vitest 要驗證：每一層在影片題、搶答暫停、旁白三種狀態下的音量都照表走。

### PR0（併在 PR1 裡）：開場點亮音效
**「聲音就緒」的條件**：AudioContext 狀態是 running，而且 🎵 開關是開的。

大螢幕：
- 大廳中央有一顆大鈕「點一下開啟音效與氣氛」。
- 按下去會解鎖 AudioContext，把 🎵 和語音兩個開關都打開，並記住設定。
- 之後主持人仍可用原本的 🎵、語音開關個別關掉。
- 🎵 關掉時，音樂、王戰效果、環境音都不響，主持人效果照響。
- 語音關掉時只影響旁白。

回報給主持人頁：
- 大螢幕在聲音就緒狀態改變時送 `SCREEN_SOUND {ready}`，例如解鎖、開關切換、重新連線之後。
- 房間記住每個有金鑰的大螢幕的最新狀態，在 STATE 裡給主持人一個 `screenSound`，值是 `ready`、`muted` 或 `none`（沒有大螢幕連著）。
- 有多個大螢幕時，只要有一個就緒就算 ready。
- 大螢幕斷線時，它的狀態就移除。

主持人頁：
- 遊戲已開始、而且 `screenSound` 不是 ready 時，頂端顯示一行黃字「大螢幕還沒開聲音，去點一下」。
- 變成 ready 就自動消失，並短暫顯示「🔊 大螢幕聲音已就緒」。
- 主持人故意關 🎵（例如自己放歌）時，黃字可以按「知道了」收起，直到下次重新連線或 🎵 再打開又關掉才再出現。語音開關不算進 ready，旁白關掉不會跳警告。

### PR1：王戰緊張感（全部自動，只動大螢幕和聲音）
**① 王登場**
- 改造現有的王房轉場（`lib/transitions.ts` 的 boss 轉場、`components/transition-overlay.tsx`）。觸發時機和優先順序照舊：每個大螢幕連線第一次看到王房時播一次，跟現有轉場一樣。之後進王房的隊伍照舊播 boss-join 旁白。
- 演出內容：畫面暗下（題目和倒數仍看得到）加低音轟鳴，王的剪影亮起，名字大字砸下，畫面震一下。總長不超過 2.5 秒。
- 不延後出題，也不碰伺服器的計時。演出疊在已經出好的題目上面，跟現在的轉場一樣，播完就淡出。
- 現有的王房警報橫幅（`BOSS_ALARM`）和最後衝刺的優先規則都不變。

**② 答錯 → 王格擋反擊**
- 動畫只演現有規則（攻擊沒打到），不扣血，也不顯示隊伍血條。
- 流程總長 1.4 秒：
  - 0–0.6 秒：王蓄力，發光並發出警告音。
  - 0.6–0.9 秒：格擋，攻擊被彈開。
  - 0.9–1.4 秒：反擊。王撲向鏡頭，畫面震動，邊緣紅閃一次。
- 只在王房答錯時播（一般房間答錯照舊）。跟其他反應的順序：現有的 `retry` 音效改在 1.4 秒反擊結束時播。答錯旁白照現有時機，聲音照分層表處理。王房沒有「重答／逃跑」選擇：答錯的紅格照現有規則停 2 秒，1.4 秒的反擊在這 2 秒內播完。手機照現有時機，不等動畫。

**③ 倒數最後 5 秒心跳**
- 只在王房、而且有作答倒數時才播。沒有設作答時間、搶答階段、等待擲骰或鎖定、影片還沒播完時，房間不會給倒數，所以也沒有心跳。這些情況照舊。
- 心跳直接排在 AudioContext 的時鐘上，速度從每秒 1 下加快到每秒 2.5 下，取代王房最後 5 秒的 `ANSWER_TICK`。答完、時間到、靜音時立刻取消。
- 畫面邊緣的紅暈跟著心跳一明一暗。紅暈只在畫面邊緣，不閃整個畫面，亮度變化不超過每秒 3 次。

**④ 王低血暴走**
- 門檻：目前這個階段的血條剩不到 1/3（`bossHp ≤ bossMaxHp/3`），每個階段各自計算。
- 進入暴走時：音樂先停 0.5 秒，再換成更快、加鼓聲的王戰版本（新的 `Song`）。王變紅並微微抖動，血條變紅。
- 換階段（`boss-phase`）時，用現有的換階段演出，音樂回到一般王戰版。新階段血條掉到 1/3 時會再暴走一次。
- 同一擊同時造成低於 1/3 和換階段時，以換階段為準，不播暴走。
- 王被打倒、新遊戲、大螢幕在王戰中途重新連線時：一律依目前的 STATE 重算（血量低於 1/3 就直接是暴走版），不補播「先靜再爆」。

### PR2：主持人加料鈕（三顆）
> **站長決定（2026-11-12，/autoplan run 2 UC1）**：「先拿掉螢幕變暗」。PR2 只做 ⚡ 雷聲、👹 低吼兩顆鈕。🌑 螢幕變暗、`HOST_DIM`、`screenDim` 都不做，移到 TODOS.md（P3）。下面和 Review record 裡寫到 🌑、`HOST_DIM`、`screenDim`、`DIM_ALPHA`、`dimVisible` 的地方，PR2 一律不做；其餘照 gate 的建議（D1、D2、D3、D4）。房間轉發給大螢幕的訊息叫 `SCREEN_EFFECT`（D4）。

- **位置**：主持人頁最上面一排三顆大鈕，單手按得到：
  - ⚡ 雷聲：邊緣白閃一次，加雷聲。
  - 👹 低吼：畫面一震，加低吼。
  - 🌑 螢幕變暗：切換開關。
- **新訊息** `HOST_EFFECT {effect: "thunder" | "growl"}`：
  - 房間只接受帶主持人金鑰的連線送來的這個訊息，玩家手機和沒金鑰的大螢幕送來的一律丟掉。
  - 伺服器端限頻，每 1 秒最多一次，多的丟掉。
  - 房間只轉發給大螢幕連線。
  - vitest 驗證：手機送來會被拒絕，連按會被限頻。
- **螢幕變暗的狀態放在房間**：
  - 主持人送 `HOST_DIM {on}`，同樣只收主持人的訊息、同樣限頻。
  - 房間把 `screenDim` 放進 STATE。大螢幕重新整理或重新連線後，照 STATE 恢復變暗；主持人鈕也照 STATE 顯示目前是開還是關。
  - 自動解除的時機：遊戲結束、影片題開始播放（題目要看得清楚）。
- **影片題播放中**：雷聲、低吼兩顆鈕變灰。`clipPlaying` 由房間現有狀態推出（目前題目是影片題，且還沒收到 SCREEN_CLIP_ENDED／SCREEN_CLIP_ERROR），放進 STATE，PR2 不加第三個訊息。大螢幕在自己的影片播放中收到 HOST_EFFECT 一律丟掉，不播聲音也不閃。
- **閃光安全**：雷聲只在邊緣白閃，不是全螢幕；受限頻保護，每秒最多一次。

### PR3：房間氛圍＋揭霧一刻
- **環境音**：每間房一種小聲循環的合成環境音，例如洞穴滴水、風聲、營火劈啪。依房間序號輪流分配，不需要新資料。
- **揭霧**：隊伍走進新房間時，霧被吹開的動畫加開門聲，新房間亮一下。沿用現有的 pawn 抵達動畫（map-strip 的 `arrived`）。
- **聲音處理**：照聲音分層表，影片題靜音、旁白時變小聲，和音樂的音量比例要先調平衡。

## Success Criteria
- **點亮音效**：開場點一下之後，大螢幕的音樂、效果音、旁白都聽得到，主持人頁顯示「🔊 大螢幕聲音已就緒」。
- **王戰效果**：王登場、王格擋反擊、王房最後 5 秒心跳、低血暴走都會自動出現，主持人不用按任何東西。心跳只在有作答倒數時出現。
- **不蓋題目**：影片或聲音題播放中，以及搶答後的暫停中，不會有任何環境音或王戰效果音蓋過題目。
- **主持人鈕**：主持人判答案時，單手按得到三顆鈕。螢幕變暗在大螢幕重新整理後仍然維持。
- **閃光安全**：整個大螢幕在任意 1 秒內合計不超過 3 次閃光，效果重疊時也一樣（vitest 驗證共用閃光預算，用同一個單位（亮起再暗下算一次）：心跳脈動中加雷聲，任意 1 秒內不超過 3 次）。開啟減少動態時不閃也不震。
- **檢查**：每個 PR 都通過 vitest、兩個 tsc、lint、check:bundle、check:docs 和 CI 的 e2e，canary 結果是 HEALTHY。
