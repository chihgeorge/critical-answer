# Question bank guide

How to change the question bank, the format rules, and how to recover when something goes wrong.

## Default question bank

The question bank is in [data/question-bank.json](../data/question-bank.json): 8 rooms with one monster each (difficulty 1/2/2/3/4/4/5/5). The questions are in five banks for difficulty 1–5 (difficulty 2 has 16 questions, the others 12 each), plus 20 boss questions, for 84 questions in total. All are four-option multiple-choice questions (players answer on their phones, and the game judges them after the host presses 「公布答案」 (Reveal answer)), so the default bank never rolls a persuasion check (see the [full rules](rules.en.md#persuasion-check)). Where the question bank editor has saved a bank, the game keeps using the saved one; this file is used only while no bank has been saved yet (see [Question bank editor](#question-bank-editor) below). The server loads and validates it at startup (a missing id, a duplicate id, an empty question or answer, a difficulty outside 1–5, or a monster's dish with missing fields or too many characters is reported as an error at once). **Only the server reads this file**; the browser gets only the question text, never the answers. `npm run check:bundle` checks this.

When you add questions: each difficulty 1–5 bank needs at least 12 questions (up to 8 teams can each hold one question at the same time, and 4 extra make sure a flee always has a question nobody holds); the boss bank should have at least "boss HP + 10" questions (every hit and every wrong answer uses one; when the last phase runs out, it reuses questions whose answers were already revealed, and when an earlier phase runs out, the game moves on to the next phase); a question's text must not contain its own answer or any other answer in the bank (the big screen is shared); no two questions may repeat a question or an answer (`lib/question-bank.test.ts` checks this).

> The 84 default questions were drafted by AI. The user reviewed 52 of them on 2026-10-25; the 20 added in v0.14.0.0 have not been reviewed, and there is no record of the user reviewing the 12 boss questions added in v0.15.0.0. Some are current-events questions from 2026, so **the host should check the answers before the game starts**.

## Question bank editor

`/bank-editor` is the host-only question bank editor. There is a link at the bottom of the home page, or you can type the URL directly; it is not part of the actual game flow. The top right of the page has 「← 回首頁」 (Back to home). When there are unsaved changes, going home, reloading, closing the tab, pressing Back or pressing 「載入題庫」 (Load question bank) asks for confirmation first. Tabs at the top switch between 「房間」 (Rooms), the 「難度 1–5」 (Difficulty 1–5) banks and 「首領」 (Boss). The Rooms tab sets each room's difficulty (which bank it draws questions from) and reward points, and the reward points for each hit on the boss; each room's monster and the boss can also be given a dish (it counts only when all four fields are filled; all four empty means no dish). The bank tabs add, edit and delete **fill-in and multiple-choice questions**, and the tab header says which rooms draw from that bank. On the Boss tab, 「新增階段」 (Add phase) splits the boss fight into phases; each phase has a name, a rule, HP (a whole number from 1 to 20; the big screen draws one heart per HP) and its own questions. From phase 2 on, the name and rule are required; when they are blank the fields turn red and you cannot save. Deleting a phase that still has questions asks for confirmation first. The bank format number went from 1 to 2; banks saved before load as a boss with a single phase. A saved bank keeps its own boss questions and does not automatically get boss questions newly added to the default bank. A bank in the old format (questions under each room) is converted to banks by difficulty when it loads. Each question can be text, an uploaded image or a YouTube video, and can have an explanation, also in any of those media, shown with the answer after a correct answer. Multiple-choice questions have at most 4 options (the big screen has only 4 slots). Players tap and lock in an option on `/play`; after the host presses 「公布答案」 (Reveal answer), the server judges by the correct option, so the host does not judge right or wrong (see the [full rules](rules.en.md#multiple-choice-questions), [docs/designs/multiple-choice-questions.md](designs/multiple-choice-questions.md) and [docs/designs/phone-answering.md](designs/phone-answering.md)). Questions with more than 4 options in an old bank still load and play as usual, but you must cut them to 4 before you can save. A bank with a question id longer than 64 characters also cannot be saved (the phone cannot send the answer to that question); ids the editor makes itself are never that long. Images are uploaded to Cloudflare R2 and shown on both `/play` and `/screen`. Replaced images, images of deleted questions, and images uploaded but never saved are all cleaned up automatically after a grace period (so a game in progress never suddenly loses an image). The question bank is actually stored in a Cloudflare Durable Object (`BankStore`), and edits take effect at once. When `BankStore` cannot be reached, new rooms automatically fall back to the bundled `data/question-bank.json`, while the editor can neither load nor save, and image uploads return 503. Saving does a version check: if someone else changed the bank at the same time, the save is blocked (409) so you do not overwrite each other. When this version cannot read the stored bank (for example after a rollback to a version older than the bank format), the editor shows a red read-only notice as soon as it loads; the screen shows the bundled default bank, the save button is disabled, image uploads are blocked (409) and image cleanup is paused. The stored bank stays as it is; see [How to recover when the bank is stuck](#how-to-recover-when-the-bank-is-stuck) below.

Image upload needs R2 set up first; see the [deployment guide](deployment.en.md#image-upload-r2).

The page asks for `OWNER_KEY` before it can read or write the bank. When this secret is not set on the server, every request gets 403 (for local development, add a line `OWNER_KEY=...` to `.dev.vars` to test; `.dev.vars.example` does not include it). For production, use `wrangler secret put OWNER_KEY` to set a random value of ≥32 bytes; a shorter one leaves a warning in the Worker log.

## How to recover when the bank is stuck

When the editor shows 「存著的題庫這個版本讀不懂」 (This version cannot read the stored question bank), your bank is still in `BankStore` and has not been overwritten; the deployed code just cannot read its format. Games opened during this time use the default bank.

1. **Most common: a rollback to a version older than the bank format.** Deploy forward again to the version that saved the bank or a newer one (merging into `main` deploys automatically; to do it by hand, on the Worker's "Deployments" page in the Cloudflare dashboard, set that version as the current version). After it deploys, reload the editor and the notice goes away.
2. **Do not roll back to a version before v0.13.1.0.** Older versions do not have this protection: when they cannot read the bank, they save the default bank over it and your bank is gone. Since `BANK_FORMAT` in `lib/bank-store.ts` went up by 1, the floor is **v0.15.0.2**: v0.13.1.0 to v0.15.0.1 ignore the format number and drop the new fields when they save.
3. **The stored data really is broken** (the Worker log has `bank_store_corrupt`, and the latest version is already deployed): first use the error message in the log to find which question and which field breaks the format, then fix the value stored in the Durable Object. Back up the original value before you fix it.
