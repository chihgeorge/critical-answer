# Question bank guide

How to change the question bank, the format rules, and how to recover when something goes wrong.

## Default question bank

The question bank is in [data/question-bank.json](../data/question-bank.json): 8 rooms with one monster each (difficulty 1/2/2/3/4/4/5/5). The questions are in five banks for difficulty 1–5 (difficulty 2 has 16 questions, the others 12 each), plus 20 boss questions, for 84 questions in total. All are four-option multiple-choice questions (players answer on their phones, and the game judges them after the host presses 「公布答案」 (Reveal answer)), so the default bank never rolls a persuasion check (see the [full rules](rules.en.md#persuasion-check)). Where the question bank editor has saved a bank, the game keeps using the saved one; this file is used only while no bank has been saved yet (see [Question bank editor](#question-bank-editor) below). The server loads and validates it at startup (a missing id, a duplicate id, an empty question or answer, a difficulty outside 1–5, a monster that is not a catalog id, a room monster as the boss, or the boss in a room is reported as an error at once). **Only the server reads this file**; the browser gets only the question text, never the answers. `npm run check:bundle` checks this.

**Monster catalog**: the bank stores only a catalog id (for example `"slime-soft"`) for each room's monster and the boss. The name, sprite, colour and the dish it is cooked into all come from [lib/monster-catalog.ts](../lib/monster-catalog.ts); a bank cannot define its own. The catalog now has 20 room monsters and 3 bosses (`dragon` 深淵小黑龍, `kraken` 深海大王烏賊, `phoenix` 不死火鳥), each with its own sprite and dish picture; the full list and ids are in `lib/monster-catalog.ts`. The default bank's 8 rooms use 8 different room monsters (`slime-soft` 軟趴趴史萊姆, `mushroom-crumbly` 碎碎蘑菇, `ghost-shy` 害羞幽靈, `snail-slow` 慢吞吞蝸牛, `bat-hanging` 倒掛蝙蝠, `ghost-cry` 愛哭幽靈, `mimic` 寶箱怪, `skeleton-rattle` 喀啦骷髏兵), and the boss is 深淵小黑龍. With `"randomMonsters": true` at the top of the bank (「每場隨機抽怪」 in the bank editor), the monsters picked above are not used: each game draws its own, a different room monster per room (repeats only when there are more rooms than room monsters) and one of the 3 bosses, so over many games every monster shows up about as often. The default bank has this switched on. Room monsters go only in rooms, and the boss only in the boss slot. The same room monster can be in several rooms: its first appearance is plain, and each time it is defeated, its next appearance gets a small variation (a new colour, an accessory on its head and a title on its nameplate, for example 「戴王冠的軟趴趴史萊姆」 (the crowned soft slime)). Each team's look for a monster is set when the team walks into the room and stays until it leaves, whatever other teams defeat meanwhile. The order is fixed within one game, and the boss never changes. Design in [docs/designs/monster-catalog.md](designs/monster-catalog.md).

When you add questions: each difficulty 1–5 bank needs at least 12 questions (up to 8 teams can each hold one question at the same time, and 4 extra make sure a flee always has a question nobody holds); the boss bank should have at least "boss HP + 10" questions (every hit and every wrong answer uses one; when the last phase runs out, it reuses questions whose answers were already revealed, and when an earlier phase runs out, the game moves on to the next phase); a question's text must not contain its own answer or any other answer in the bank (the big screen is shared); no two questions may repeat a question or an answer (`lib/question-bank.test.ts` checks this).

> The 84 default questions were drafted by AI. The user reviewed 52 of them on 2026-10-25; the 20 added in v0.14.0.0 have not been reviewed, and there is no record of the user reviewing the 12 boss questions added in v0.15.0.0. Some are current-events questions from 2026, so **the host should check the answers before the game starts**.

## Question bank editor

`/bank-editor` is the host-only question bank editor. There is a link at the bottom of the home page, or you can type the URL directly; it is not part of the actual game flow. The top right of the page has 「← 回首頁」 (Back to home). When there are unsaved changes, going home, reloading, closing the tab, pressing Back or pressing 「載入題庫」 (Load question bank) asks for confirmation first. Tabs at the top switch between 「房間」 (Rooms), the 「難度 1–5」 (Difficulty 1–5) banks and 「首領」 (Boss). The Rooms tab sets each room's difficulty (which bank it draws questions from) and reward points, and the reward points for each hit on the boss; each room's monster and the boss are picked from a catalog menu (rooms list only room monsters, the boss slot only bosses), with the sprite and the dish that monster is cooked into shown next to it. The bank tabs add, edit and delete **fill-in and multiple-choice questions**, and the tab header says which rooms draw from that bank. On the Boss tab, 「新增階段」 (Add phase) splits the boss fight into phases; each phase has a name, a rule, HP (a whole number from 1 to 20; the big screen draws one heart per HP) and its own questions. From phase 2 on, the name and rule are required; when they are blank the fields turn red and you cannot save. Deleting a phase that still has questions asks for confirmation first. The bank format number is now 3 (monsters are stored as catalog ids). This version does not read an old format 1 or 2 bank: the editor shows a yellow notice, the screen shows the default bank, and the save button works and overwrites the old bank; to keep the old bank, see [How to recover when the bank is stuck](#how-to-recover-when-the-bank-is-stuck) below. Mid-deploy, when the frontend updates before the Worker, an editor that gets an old-format bank shows the red notice 「伺服器還是舊版，等部署完成再重新載入。」 (the server is still the old version; reload once the deploy finishes) and disables saving. A saved bank keeps its own boss questions and does not automatically get boss questions newly added to the default bank. Each question can be text, an uploaded image or a YouTube video, and can have an explanation, also in any of those media, shown with the answer after a correct answer. Multiple-choice questions have at most 4 options (the big screen has only 4 slots). Players tap and lock in an option on `/play`; after the host presses 「公布答案」 (Reveal answer), the server judges by the correct option, so the host does not judge right or wrong (see the [full rules](rules.en.md#multiple-choice-questions), [docs/designs/multiple-choice-questions.md](designs/multiple-choice-questions.md) and [docs/designs/phone-answering.md](designs/phone-answering.md)). Questions with more than 4 options in an old bank still load and play as usual, but you must cut them to 4 before you can save. A bank with a question id longer than 64 characters also cannot be saved (the phone cannot send the answer to that question); ids the editor makes itself are never that long. Images are uploaded to Cloudflare R2 and shown on both `/play` and `/screen`. Replaced images, images of deleted questions, and images uploaded but never saved are all cleaned up automatically after a grace period (so a game in progress never suddenly loses an image). The question bank is actually stored in a Cloudflare Durable Object (`BankStore`), and edits take effect at once. When `BankStore` cannot be reached, new rooms automatically fall back to the bundled `data/question-bank.json`, while the editor can neither load nor save, and image uploads return 503. Saving does a version check: if someone else changed the bank at the same time, the save is blocked (409) so you do not overwrite each other. When this version cannot read the stored bank (for example after a rollback to a version older than the bank format), the editor shows a red read-only notice as soon as it loads; the screen shows the bundled default bank, the save button is disabled, image uploads are blocked (409) and image cleanup is paused. The stored bank stays as it is; see [How to recover when the bank is stuck](#how-to-recover-when-the-bank-is-stuck) below.

**YouTube questions and music questions**: when a question's content is an image or a YouTube video, you can also fill in a 「題幹」 (prompt, up to 200 characters). The big screen, the phones and the host page show it above the image or video. A text question is its own prompt, so it cannot have one. A YouTube question can have a start and an end time (type `1:05` or `65`; it is stored in seconds; leave the end empty to play to the end), and 「▶ 試聽片段」 (preview clip) plays it in the editor. With 「只放聲音（聽歌題）」 (sound only, music question) checked, the big screen covers the video with a pixel card and plays only the sound; the picture shows when the answer is revealed (an image or video explanation shows instead, if there is one). An explanation video cannot be sound only. Videos play only on the big screen, controlled by ▶ 播放 (play), ⏸ 暫停 (pause) and ⟲ 從頭 (from the start) on the host page; phones do not embed them. Note: YouTube's policies do not allow separating the sound from the picture, so music questions suit private events only. Many record labels turn off embedding for their music videos, and the big screen then shows 「影片無法播放」 (video cannot play); before the event, try each one on the big screen with ▶ on the host page. Design in [docs/designs/youtube-questions.md](designs/youtube-questions.md).

Image upload needs R2 set up first; see the [deployment guide](deployment.en.md#image-upload-r2).

The page asks for `OWNER_KEY` before it can read or write the bank. When this secret is not set on the server, every request gets 403 (for local development, add a line `OWNER_KEY=...` to `.dev.vars` to test; `.dev.vars.example` does not include it). For production, use `wrangler secret put OWNER_KEY` to set a random value of ≥32 bytes; a shorter one leaves a warning in the Worker log.

**Game log**: when a game ends (the boss falls, or the host presses 「結束冒險」), the server stores one record in the bank's Durable Object and prints a `game_log` line to the Worker log. The record has the start and end time, the number of teams, and for each team its name, class, place, progress score, 飽足感, total turns, the round it entered the boss room and its own turns until then. It also has the score needed to enter the boss room, each room's and the boss's reward, each boss phase's HP, the phase reached, the HP left, and how many rounds the boss fight took. A round is one turn for every team. The record has no question or answer text. If the store fails, the Worker log gets `game_log_failed` and the game goes on. Enter `OWNER_KEY` and press 「⬇ 下載對局紀錄（JSON）」 to download every game as one JSON file, to tune the boss HP or the boss-entry score.

## How to recover when the bank is stuck

When the editor shows 「存著的題庫這個版本讀不懂」 (This version cannot read the stored question bank), your bank is still in `BankStore` and has not been overwritten; the deployed code just cannot read its format. Games opened during this time use the default bank.

1. **Most common: a rollback to a version older than the bank format.** Deploy forward again to the version that saved the bank or a newer one (merging into `main` deploys automatically; to do it by hand, on the Worker's "Deployments" page in the Cloudflare dashboard, set that version as the current version). After it deploys, reload the editor and the notice goes away.
2. **Do not roll back to a version before v0.13.1.0.** Older versions do not have this protection: when they cannot read the bank, they save the default bank over it and your bank is gone. Since `BANK_FORMAT` in `lib/bank-store.ts` went up by 1, the floor is **v0.15.0.2**: v0.13.1.0 to v0.15.0.1 ignore the format number and drop the new fields when they save.
3. **The stored data really is broken** (the Worker log has `bank_store_corrupt`, and the latest version is already deployed): first use the error message in the log to find which question and which field breaks the format, then fix the value stored in the Durable Object. Back up the original value before you fix it.
4. **The yellow notice 「正式站題庫是舊格式（格式 N）」 (the stored bank is in an old format)**: the bank was saved before v0.40 (format 1 or 2, with whole monsters stored in the bank), and this version does not read the old format. The screen shows the new default bank, and pressing save overwrites the old bank (the old bank's images stay in R2 for 14 days before they are deleted, so save the converted bank back before then); games opened during this time use the default bank. To keep the old bank's questions, do the following in the repo root (`local-banks/` is git-ignored):
   1. **Before you upgrade**, back it up (once the new version is live, `GET /api/bank` returns only the default bank and you cannot get the old one):
      ```bash
      mkdir -p local-banks && curl -fsS -H "Authorization: Bearer $OWNER_KEY" https://<your Worker>/api/bank > local-banks/prod-backup-2026-11-07.json
      ```
   2. Replace the monsters in the backup with catalog ids. The old editor could not rename monsters, so an old bank's monsters are always one of the 9 in the table below; recoloured ones and ones not in the catalog map to the original with the same sprite. A name that does not match stops the command and is printed:
      ```bash
      node -e '
      const fs = require("fs");
      const ID = { "軟趴趴史萊姆": "slime-soft", "害羞幽靈": "ghost-shy", "迷路史萊姆": "slime-soft", "愛哭幽靈": "ghost-cry", "守門史萊姆王": "slime-soft", "暴躁幽靈": "ghost-shy", "熔岩史萊姆王": "slime-soft", "冰霜愛哭鬼": "ghost-cry", "深淵小黑龍": "dragon" };
      const bank = JSON.parse(fs.readFileSync(process.argv[1])).bank;
      const toId = (m, where) => { const id = typeof m === "string" ? m : ID[m && m.name]; if (!id) { console.error("對不到：" + where + " " + JSON.stringify(m)); process.exit(1); } return id; };
      bank.rooms.forEach((r, i) => { r.monster = toId(r.monster, "rooms[" + i + "]"); });
      bank.boss.monster = toId(bank.boss.monster, "boss");
      fs.writeFileSync(process.argv[2], JSON.stringify(bank, null, 2));
      ' local-banks/prod-backup-2026-11-07.json local-banks/prod-converted.json
      ```
   3. After the upgrade, save the converted bank back with the stored version (a version mismatch returns 409; fetch the version again and retry):
      ```bash
      V=$(curl -fsS -H "Authorization: Bearer $OWNER_KEY" https://<your Worker>/api/bank | node -pe 'JSON.parse(require("fs").readFileSync(0)).version')
      node -e 'const fs=require("fs");process.stdout.write(JSON.stringify({bank:JSON.parse(fs.readFileSync(process.argv[1])),version:+process.argv[2]}))' local-banks/prod-converted.json "$V" | curl -fsS -X PUT -H "Authorization: Bearer $OWNER_KEY" -H "Content-Type: application/json" --data-binary @- https://<your Worker>/api/bank
      ```
   4. Reload the editor: the yellow notice is gone, and each room's menu shows its original monster.
